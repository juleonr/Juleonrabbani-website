Ask Mallard · The revised planning approach

From a question
to a design

Mallard is changing the order in which it builds a study plan. It will first pin down exactly what the question is asking for, as a typed estimand, and confirm it with the clinician. Rules and a tested code library then decide which analysis methods are valid. Only after that does the AI recommend a design and set out the alternatives.

Proposed approach, in development. This page follows Mallard's draft design-selector and code-library specs from 23 September 2026, which have not been adopted yet. Today, Mallard's AI drafts the design first, and the code library is consulted only when the plan's code is written.

What changes

Today

  1. Question
  2. AIDesign briefdesign, estimand and alternatives in one pass
  3. Reviewer and code checks
  4. Study, analysis, write-up
  5. LibraryCode stepone exact match, or “not covered”

Proposed

  1. Question
  2. Typed estimand
  3. Clinician confirms
  4. Rules + libraryValid methodscovered, valid without code, or excluded
  5. AIDesign + alternativesproposed inside the valid set

Two things move. The code library goes from the last step to the middle, where it helps decide what is valid. The AI's design choice moves from the start to the end, so it works within limits the rules have already set. Dashed boxes are written by the AI; green boxes use the code library.

The sections below follow one question through each stage. It is Mallard's own worked example. The library results are read from the metadata of the 72 entries the app ships today; the rules, registry and confirmation step are proposed.

01

Start with the question

A clinician states what they want to know and what data they have. They do not need to name a design or a method.

Does scheduling a follow-up appointment before discharge change 30-day unplanned readmission?

Data: discharge and scheduling records from a hospital medicine service.

What happens here

  • A readiness check lists what is still missing before a plan can be written. Anything the clinician has already answered is dropped from the list.
  • Mallard asks sharpening questions only when the answer would change the plan. For example: does the scheduling system record when an appointment was created, or only when it takes place?
02

Why this comes first

  • Competing events is a single yes/no field, and it changes which methods are valid. A standard Cox model treats a patient who died as simply censored, which overstates readmission.
  • Sampling structure replaces a yes/no “clustered” flag with the code library's own four values: independent, clustered, matched, or survey. That lets the rules see matched case-control and survey designs, which they cannot today.
  • Mediation records whether the question asks how much of an effect works through a middle step. Today that is detected by searching the plan's wording.
03

Confirm the estimand Planned

Every later rule trusts the typed facts, so a mistyped question gets confidently wrong answers. Before any design is proposed, the clinician confirms the facts that matter most.

  • Target: is this about a cause, an association, a description, or a prediction? Here: an association.
  • Assignment: was the comparison randomized? Here: no, the groups are observed.
  • Will each case be matched to specific controls (for example, on age and sex)? Here: no.
  • Is part of the question how much of the effect works through a middle step? Here: no.

Why it is needed

  • In Mallard's 23 September audit, 7 of 28 plans typed a fact differently from the reference answer, and one randomized trial was typed as descriptive three times.
  • “Not sure yet” is an allowed answer; it simply stops the related rules from firing. A value read from the description is shown back to the clinician, never applied silently.
  • This step is named in the draft spec but will be specified separately, so its exact form may change.
04

Find the valid methods

Rules on the typed facts decide which analysis methods are valid. A registry lists every method, whether or not code exists for it. The code library is the verified part of that registry: its entries have R and/or Python code that has been run on a test dataset and checked against expected output. Each method ends up in one of three states.

Covered

Valid for this estimand, with verified code in the library.

Valid, no verified code

Valid, but the library has no entry yet. The plan can still use it, and says the code is not verified.

Excluded

A rule names why it does not fit, e.g. “a randomized comparison is not sized as a single group”.

Rules decide validity

Whether a method is valid depends on rules over typed facts, not on whether code exists. In the audit, when the library had 16 entries, only 17 of 75 plans matched any of them, and most of the rest were sound plans.

Exact, not nearest

Methods are not scored or ranked. The standard Cox model agrees on four of five fields and is still excluded, because it treats a death as an ordinary dropout.

Nothing is substituted

When no covered method fits, the plan says so. It does not quietly swap in a method for a different estimand that the library happens to have.

05

Recommend a design, show the alternatives

The AI proposes the recommended design and the alternatives, working inside the set of valid methods. The rules narrow the analyses and sample-size methods; choosing among designs is still the AI's job. Each option shows what it costs and what it would let you claim.

RecommendedAdjusted associationMonthsExisting records

Retrospective cohort from discharge and scheduling records, with death as a competing risk

The exposure is already recorded at discharge, and the outcome is recorded in the same system. A cohort can therefore answer the question from data that already exists, without paying to collect new data. Because the two groups differ systematically, the analysis adjusts for confounders, and the result is reported as an association rather than an effect.

Primary analysis · covered
Cause-specific Cox regression, reported as an adjusted hazard ratio
Companion · covered
Fine-Gray regression for the cumulative incidence of readmission

Design-fit checks to run before committing

  1. At least 95% of appointments have a creation time before the discharge time.If not: restrict to reliable timestamps, or switch to the case-control design.
  2. Deaths recorded in the system are within 10% of an external death count.If not: report the cause-specific hazard only.
  3. At least 10 readmissions per covariate in the adjustment set.If not: widen the record window or reduce to a minimal sufficient set.

Why this order

When the design is chosen before the estimand is fixed, it is easy to reach for a familiar method that answers a slightly different question. Here, a standard Cox model would ignore deaths. Fixing and confirming the estimand first, and letting rules decide what is valid before the AI chooses, means the recommended design comes with methods that fit the question actually asked, and says plainly where verified code exists.

Status: the rules, the method registry, the two new intake facts and the confirmation step are drafts awaiting the owner's decisions. The first step proposed is to run the rules alongside plan generation, without changing any plan, until an audit shows they never exclude a method that expert reviewers accept.
